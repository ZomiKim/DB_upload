# Local DB 정합성 자동화 매크로

팀 단위 로컬 DB 환경에서 **데이터 버전 불일치**와 **FK 기반 무결성 깨짐**을 구조적으로 해결하고, **수작업 동기화를 자동화·배포 가능한 형태**로 전환한 프로젝트입니다.

---

## 강조 포인트

| 영역 | 내용 |
|------|------|
| **문제 분석** | 원인을 “데이터 버전 분산 / 참조 무결성 / 프로세스 비용”으로 구조화해 정의 |
| **무결성·FK** | PK/FK 의존 그래프를 기준으로 추출·적재 순서를 설계해 Referential Integrity 보장 |
| **자동화** | 반복 INSERT·수동 반영을 CSV 기반 일괄 적재(idempotent) 매크로로 대체 |
| **팀 배포** | Windows `.exe` 단일 배포로 동일 DB 스냅샷을 전원이 공유하는 전략 수립 |

---

## 1. 프로젝트 개요

- **프로젝트 유형**: 팀 기반 애플리케이션 개발  
- **환경 제약**: 중앙 DB 서버 미구축(학원 환경에서 인프라 지원 제한)  
- **문제 상황**: 팀원 각자 PC에 로컬 DB를 두고 개발하던 과정에서, **데이터 버전이 어긋나며 FK 참조 오류·정합성 문제가 반복** 발생

---

## 2. 문제 정의 (Problem Statement)

다음 네 가지를 **연쇄 구조**로 정리했다.

1. 팀원별 로컬 DB의 **데이터 버전·내용이 상이**함  
2. 그 결과 **PK/FK 관계가 어긋나** 기능 테스트가 실패함  
3. 데이터 변경 시마다 담당자가 **INSERT를 수동 작성**하고 팀원 PC DB에 개별 반영 → **평균 1~2시간** 소요  
4. 개발이 진행될수록 변경 빈도가 늘어 **유지 비용이 기하급수적으로 증가** — **수작업 동기화는 확장 불가**

---

## 3. 해결 전략 (Solution Approach)

### 목표

- **기준 DB(Master)**를 중심으로 한 **일관된 데이터 배포** 체계  
- **PK/FK 무결성 유지**  
- **수동 INSERT 작업 제거**

---

## 4. 설계 로직

### 기준 DB 선정

정합성의 단일 기준이 되는 로컬 DB **1개를 MasterDB로 지정**한다.

### FK 의존성 기반 추출 전략

PK/FK 관계를 분석해 **FK의 원류(상위 테이블)부터 순차적으로** 각 테이블을 **개별 CSV**로 추출한다.

**예시 흐름**

```
User
├── Order
│   └── OrderDetail
```

→ 적재·추출 순서: **User → Order → OrderDetail** (CSV 생성·로드 순서와 동일하게 맞춤)

**이렇게 설계한 이유**

- FK 제약 위반을 줄이고, 로드 시점에 **Referential Integrity**를 만족시키기 위함  
- 상위 행이 먼저 존재해야 하위 FK 행을 안전하게 넣을 수 있음

### 자동 동기화 매크로 앱

**처리 파이프라인**

앱 실행 → **내장 CSV 로드** → 동명 테이블에 대해 **기존 데이터 정리(TRUNCATE 또는 DELETE)** → **CSV 기반 bulk insert**

**역할 요약**

- 동명 테이블 매핑  
- **반복 실행해도 같은 결과**를 얻는 **idempotent** 동작(환경 재현용)

### 팀 단위 배포 전략

- 해당 기능을 **Windows 실행 파일(`.exe`)**로 빌드  
- 팀원 전원에 배포 → **실행 한 번으로 동일 DB 상태**에 근접  
- **개발 환경 표준화**(로컬 스키마 전제 하에 데이터 시드 일치)

---

## 5. 기술적 기여 (Technical Contribution)

1. **데이터 정합성 구조 설계**  
   - PK/FK 의존성 기반 **추출·적재 순서** 수립  
   - Referential Integrity를 고려한 **로드 순서** 설계  

2. **자동화 매크로 프로그램**  
   - CSV 파싱  
   - 테이블 초기화 및 재적재 자동화  
   - 동명 테이블 매핑  
   - **반복 실행 가능한 idempotent 구조**

3. **수작업 프로세스 제거**

   | Before | After |
   |--------|--------|
   | 수동 INSERT 작성 | **exe 1회 실행** |
   | 개별 PC 접속·쿼리 실행 | **전체 데이터 동기화 자동화** |
   | 오류 수정 반복 | 인적 오류·반복 피로 감소 |

4. **개발 생산성**  
   - 동기화 시간: **기존 1~2시간 → 수 분 이내**  
   - 테스트·로컬 환경의 **데이터 기준 통일**

---

## 6. 성과 (Impact)

- 동일 학원 과정에서 **약 15명 규모**의 실사용자 확보 경험과 연계 가능한 배포 단위  

| 구분 | 개선 전 | 개선 후 |
|------|---------|---------|
| 데이터 반영 시간 | 1~2시간 | **약 2분 이내** |
| 로컬 DB 간 정합성 | 오류 빈번 | **자동화로 정합성 리스크 대폭 감소** |
| 프로세스 | 담당자·수동 쿼리 의존 | **표준 시드 + exe 배포** |
| 운영 피로도 | 제거·재시도 반복 | **단일 실행으로 수렴** |

---

## 요약

이 프로젝트는 **문제를 구조적으로 분석**하고, **데이터 무결성과 FK 의존성**을 설계의 중심에 두며, **반복 수작업을 자동화**했고, **팀 전원이 같은 데이터 스냅샷을 쓰도록 하는 배포 전략**까지 포함한 **로컬 DB 정합성 자동화** 사례이다.
